# P8779 推导部分和 —— 对拍套件

三个文件各干一件事，改题只换这三个的内容，跑法不变：

| 文件 | 作用 |
|---|---|
| `gen.py` | 随机小数据生成器，`python gen.py <种子>`，同一个种子永远出同一份数据 |
| `brute.py` | 暴力（前缀和图 + BFS 推值），故意不用并查集 |
| `run.py` | 一键：编译 `..\..\luogu\P8779.cpp` → 跑 300 轮 → 打印第一个反例 |

## 跑法

```bash
cd D:/.CODE/OI/_debug/p8779
python run.py            # 默认 300 轮
python run.py 50         # 想跑快一点
python gen.py 7          # 只看第 7 号种子生成的数据长什么样
```

反例（输入 + 两边输出）直接打在屏幕上，数据很小，复制粘贴就能本地复现：
`python gen.py <出问题的种子号>` 能重新打印同一份数据。

## 三个容易搞砸的地方

1. **数据必须合法**。这题保证「无矛盾」，所以 `gen.py` 不能随机 S，
   要先随机真实数列 A，再用前缀和反推每条已知部分和。否则生成的数据本身不存在，
   暴力和你的程序谁"错"都没有意义。
2. **暴力必须换算法**。用并查集写暴力 = 两边一起犯同一个错，对拍永远绿。
   这里换成「前缀和图上 BFS 推值」。
3. **数据要脏**。纯随机的边往往一两条就并到根，测不出多层 `father` 的错，
   所以 `gen.py` 有 45% 概率故意造一条长链（单元素约束，顺序打乱）。

## 出了反例之后

1. 手动缩：n 缩到 2、S 改成 0/±1，只要还错就继续缩 —— 缩到能一眼推完的大小。
2. 在 `setunion` / `setfind` 里临时 `cerr << father[...] << ' ' << dist[...]`，
   把这个小反例逐行跑一遍，跟你纸上手算的表对齐，第一处不一致就是病灶。
3. 改完重跑对拍，看「错的组数」降到 0。只看样例通过不算修好。
