# 对拍工具（OI 排查「样例过、测试点挂」用）

三步：写暴力 → 写随机小数据生成器 → 逐组 diff。人眼找不出的错，对拍能替你造出反例。

## 用法

```bash
cd D:/.CODE/OI

# 1. 编你的解（一定用评测机的优化级别，本地 -O0 通过不算数）
g++ -O2 -std=c++17 -Wall -Wextra -o _debug/mine.exe luogu/P3958.cpp

# 2. 编暴力（每个题写一份，照 p3958_brute.cpp 改）
g++ -O2 -std=c++17 -o _debug/p3958_brute.exe _debug/p3958_brute.cpp

# 3. 对拍，默认 300 轮
python _debug/stress.py _debug/mine.exe _debug/p3958_brute.exe _debug/p3958_gen.py 300
```

输出示例：

```
轮数 100，出错轮数 100，逐组对比 0 组，错的 0 组
第一个反例： CRASH rc=3221225477
```

`rc=3221225477` 就是 0xC0000005，访问越界。出错轮数 > 0 时，会直接打印第一个反例的输入和两边输出。

## 生成器的三条硬要求

1. 第一个参数是种子，同一个种子必须复现同一份数据。
2. 数据要**小**（暴力跑得动），n ≤ 6 就够触发绝大多数逻辑错。
3. 数据要**脏**：负坐标、重合点、刚好接触（距离 == 2r）、n = 1、极值边界。让随机分布覆盖到你手工测试永远想不到的角落。

## 出反例之后

1. 手工缩小：把 n 减到最小、坐标改成 0、r 改成 1，保住「错」的性质。
2. 问自己一句「我的心智模型漏了哪种情形」，而不是从头读代码。
3. 改完重跑对拍，看错的组数降到 0。
