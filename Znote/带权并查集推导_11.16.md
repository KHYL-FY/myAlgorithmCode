# 带权并查集：`dist[lf] = dist[r] - dist[l] + v` 是怎么推出来的

以 P8779 推导部分和为例。整道题只有这一处需要"推"，其他都是模板。

---

## 0. 识别信号：什么时候该想到带权并查集

- 题目只给出"某两段/两点之间的差（或和）"，问你"另一段"
- 没有绝对量，只有相对关系
- 关系可以**传递**：知道 a 和 b 的关系、b 和 c 的关系，就能推出 a 和 c

满足这三条，就是带权并查集的题面。等价说法：差分约束、前缀和关系图、加权图连通性。

---

## 1. 两个量，先分清

| 量 | 含义 | 可知性 |
|---|---|---|
| `T[i]` | 真实前缀和 `A1+A2+…+A(i-1)` | **不可知**，只有差可知 |
| `dist[x]` | 并查集里存的数 | 可以算出来 |

程序里从头到尾没算过一个 `T`。`dist` 只是 `T` 的**替身**，替身必须和本体保持一条固定的关系式——这就是整个技巧的全部内容。

---

## 2. 下标的约定（P8779 特有，但思路通用）

节点 `i` 代表"前 `i-1` 项的和"：

```
T[i] = A1 + A2 + ... + A(i-1)        T[1] = 0
```

于是：

- 约束 `l..r = v` ⟺ `T[r+1] - T[l] = v`（所以 `setunion(l, r+1, v)`）
- 查询 `l..r` ⟺ `T[r+1] - T[l]`（所以 `query(ql, qr+1)`）

两处必须严格一致。写带权并查集的第一步永远是：**把"区间"翻译成"两点之差"**，并且上下两处翻译得一模一样。

---

## 3. `dist` 的定义是被查询式定死的

这一步是卡住最多人的地方。`dist[x]` 到底是"根减自己"还是"自己减根"？**不是随便选的，由你查询怎么写决定。**

查询里写的是 `dist[l] - dist[r]`，而它必须等于正的 `T[r] - T[l]`：

```
dist[l] - dist[r] = T[r] - T[l]
```

能把两个括号里的根消掉、又得到 `T[r]-T[l]` 的，只有一种：

```
dist[x] = T[find(x)] - T[x]          （根减自己）
```

如果定义成 `T[x] - T[root]`，查询就得写成 `dist[r] - dist[l]`，所有符号反过来。

**一句话：查询式就是 `dist` 定义的说明书。**

### 三条推论（后面每步都靠它们）

1. **`dist[根] = 0`**（自己减自己）。记住这条，后面是杀招。
2. 同块内任意两点：`dist[x] - dist[y] = T[y] - T[x]`——**根被消掉**。所以不需要绝对前缀和，只有差也够用。
3. 路径压缩 `dist[a] += dist[t]` 是恒等式展开：

```
T[根]-T[a] = (T[根]-T[t]) + (T[t]-T[a])
  新dist[a]     压缩后dist[t]    旧dist[a]
```

一个加法就够。

---

## 4. 合并那条边的四步推导

设 `a = l`，`b = r+1`，`ra = find(a)`，`rb = find(b)`。题目条件：

```
T[b] - T[a] = v
```

**第 1 步**：把两个端点按定义反解成 `T`：

```
T[a] = T[ra] - dist[a]
T[b] = T[rb] - dist[b]
```

**第 2 步**：代入条件：

```
v = (T[rb] - dist[b]) - (T[ra] - dist[a])
```

**第 3 步**：整理出"两根之间"的差：

```
T[rb] - T[ra] = v - dist[a] + dist[b]
```

**第 4 步**：你决定让 `father[ra] = rb`。那么合并之后 `ra` 的父就是 `rb`，按定义它的 `dist` 必须是：

```
dist[ra] = T[rb] - T[ra] = dist[b] - dist[a] + v
```

换回代码里的参数名（`a→l`，`b→r`）：

```cpp
dist[lf] = dist[r] - dist[l] + v;
```

### 口诀

> 新边权 = v + 右端点到根的积累 − 左端点到根的积累

直觉：`v` 只告诉你这两点差多少，它不知道两个根各自"站在"哪个基准上；`dist[r]` 和 `dist[l]` 就是这两个基准的差值，必须补回去。

还有一条约定必须记住：**合并只新建这一条边**，别的节点 `dist` 一个都不动，剩下的差值全部交给 `find` 在路径压缩时用那个加法累出来。

## 5. 错了会怎样：一组实测对照

数据：`n = 4`，三条约束 `1..2 = 5`、`3..4 = 9`、`2..2 = 7`，询问 `1..2`、`2..2`、`3..4`（正确答案 `5 7 9`）。

执行过程（节点 1..5，`dist` 是 `find` 之后的值）：

| 阶段 | father | dist[1..5] |
|---|---|---|
| 初始 | `1 2 3 4 5` | `0 0 0 0 0` |
| 约束 `1..2=5` 后 | `3 2 3 4 5` | `5 0 0 0 0` |
| 约束 `3..4=9` 后 | `3 2 5 4 5` | `5 0 9 0 0` |
| 约束 `2..2=7` 后 | `3 5 5 4 5` | `5 16 9 0 0` |

两个式子跑出来的答案：

```
dist[lf] = dist[b] - dist[a] + v    →  5   7   9   正确
dist[lf] = dist[lf] - dist[rb] + v  →  5  -2   9   错误
```

拆第三次合并（`a=2, b=3`，`find(2)=2`，`find(3)=5` 且 `dist[3]=9`）：

- 正确：`dist[2] = dist[3] - dist[2] + 7 = 9 - 0 + 7 = 16`
  校验：`T[5]-T[2] = (T[5]-T[3]) + (T[3]-T[2]) = 9 + 7 = 16` ✔
- 错误：`dist[2] = 0 - 0 + 7 = 7`
  于是查询 `2..2` 变成 `dist[2] - dist[3] = 7 - 9 = -2`，正确答案是 `7` ✘

### 为什么错的那个式子看起来还挺像回事

```
dist[lf] = dist[lf] - dist[rb] + v;
```

`lf`、`rf` 是 `find` 的返回值，**都是根**。由推论 1，`dist[lf] = dist[rf] = 0`，这一项恒等于 0，式子退化成 `dist[lf] = v`——`dist[l]` 和 `dist[r]` 里攒的偏移全被扔了。

它只在"两个端点恰好都是根"的时候是对的。上面那个例子里**前两次合并都没错**（那时两个端点都是根），第三次才炸。这就是这类错最难查的地方：小数据时对时错，正确率随数据规模下降。

---

## 6. 通用套路：换一道题照着这四步走

1. **选前缀量**：把"区间"翻译成"两点之差"，写清节点 `i` 代表什么
2. **从查询式倒推 `dist` 定义**：先决定查询怎么写，`dist` 的符号就定死了
3. **合并时两端各写 `T[根] − dist`**，代入条件解出新边
4. **自检**：手推三条约束，其中一条的某个端点**必须是已经在树里的非根节点**——这是唯一能暴露符号错误的结构

第 4 步的检查比读十遍代码有用。构造方法是：先合并两条互不相交的约束，再用第三条把它们连起来。

## 7. 完整代码（P8779 AC 版核心）

```cpp
ll setfind(ll a, vector<ll> &father, vector<ll> &dist)
{
    if (a != father[a])
    {
        ll t = father[a];
        father[a] = setfind(father[a], father, dist);
        dist[a] += dist[t];          // 路径压缩：把自己到根的差累起来
    }
    return father[a];
}

void setunion(ll l, ll r, ll v, vector<ll> &father, vector<ll> &dist)
{
    ll lf = setfind(l, father, dist);
    ll rf = setfind(r, father, dist);
    if (lf != rf)
    {
        father[lf] = father[rf];
        dist[lf] = dist[r] - dist[l] + v;      // ← 全文唯一需要推导的一行
    }
}

ll query(ll l, ll r, vector<ll> &father, vector<ll> &dist)
{
    ll lf = setfind(l, father, dist);
    ll rf = setfind(r, father, dist);
    if (lf != rf) return LLONG_MAX;            // 不同块 = 推不出来
    return dist[l] - dist[r];                  // 这里定死了 dist 的符号
}
```

调用：`setunion(l, r + 1, sum)`，`query(ql, qr + 1)`。

## 8. 易错点清单

- **定义和查询式不一致**：`dist` 是"根减自己"，查询却写 `dist[r]-dist[l]`，答案全部反号
- **合并式里出现 `dist[根]`**：那一项恒为 0，说明你把 `l/r`（端点）和 `lf/rf`（根）搞混了
- **忘了先 `find` 再用 `dist[l]`、`dist[r]`**：路径没压缩，拿到的不是"到根的差"
- **`r+1` 只在一边加**：约束加 `r+1`、查询不加（或反过来），整道题错位
- **推不出来用 0 当哨兵**：真正的部分和可能就是 0，必须用根是否相同来判断，不能用返回值
- **数据范围**：`S` 到 `1e12`，n 到 `1e5`，前缀和是 `1e17` 量级，必须 `long long`；判"UNKNOWN"不能用 `INT64_MAX` 参与减法

## 10. 一句话总路线

> 我想表达的是"两点之差" → 并查集只能存"点到父亲的相对量" → 那就把 `T[x] = T[根] − dist[x]` 代入题目条件，解出唯一要求的未知量 `dist[ra]`。

不是灵光乍现。**定义 → 代入 → 解未知量**，三步而已。
