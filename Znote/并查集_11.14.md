# 并查集 DSU（Disjoint Set Union）

> 维护若干个「等价类」的合并与查询。只支持合并，不支持删除和拆分。
> 一个集合 = 一批被认定「等价」的元素。

## 一、基本操作

| 操作 | 作用 | 复杂度 |
| --- | --- | --- |
| `find(x)` | 找 x 所在集合的代表元（根） | 近似 O(1) |
| `union(x, y)` | 合并两个集合 | 近似 O(1) |
| `same(x, y)` | 判断是否同一集合 | 近似 O(1) |

### 路径压缩

`find` 时把沿途的点直接挂到根上，下次查询就是一步。

### 按秩合并

合并时把矮的树挂到高的树下面，防止退化成一条链。维护 `sz[]` 或 `rank[]`。
只写路径压缩已经够用；两者都写才是严格的 O(α(n))。

### 模板

```cpp
int fa[N];

int find(int x) {
    if (fa[x] != x) fa[x] = find(fa[x]);   // 路径压缩
    return fa[x];
}

void unite(int a, int b) {
    a = find(a);
    b = find(b);
    if (a != b) fa[a] = b;
}

bool same(int a, int b) {
    return find(a) == find(b);
}
```

### 什么时候该想到它

- 关系是「等价 / 同类 / 连通」，要一条一条加进来
- 要判断「这两个东西是不是已经被归成一类了」
- 离线处理，只加不删

---

## 二、并查集为什么表达不了「不同」

并查集里的「同一集合」是**等价关系**：自反、对称、传递。

而「不同」不是等价关系，因为**它没有传递性**：

$$
a \neq b,\; b \neq c \;\nRightarrow\; a \neq c
$$

反例就是 `1 — 2 — 3` 这条链：1 和 2 不同、2 和 3 不同，结论却是 **1 和 3 相同**。

所以「不同」这个关系本身没法映射成一个集合 —— 不是写法问题，是结构不匹配。

### 第二个坑

普通并查集回答「不在同一集合」时，把两种完全不同的情况混成了同一个答案：

| 情况 | 含义 | 并查集能区分吗 |
| --- | --- | --- |
| 已知不同 | 有约束明确说过这俩不同 | ❌ |
| 完全未知 | 没有任何约束碰过它，爱怎样怎样 | ❌ |

这两种在并查集里长得一模一样。

> **所以「不 union 就等于记住了不同」是错的 —— 那只是「没记住」。**

## 三、拆点法（补点法）：让并查集能处理「必须不同」

### 核心改写

$$
a \text{ 和 } b \text{ 不同} \;\Longleftrightarrow\; a \text{ 和 } b \text{ 的对立面相同}
$$

「相同」是等价关系，能进并查集，路就通了。

### 建点

| 编号 | 含义 |
| --- | --- |
| `1 … n` | 断言「i 在 A」 |
| `n+1 … 2n` | 断言「i 在 B」，即 i 的对立面 |

- `i` 与 `i + n` 天然互斥，这是**定义**，不需要 `union`
- 此时「同一集合」的新含义 = **这几句断言必须同真同假**

### 翻译约束

要求 `a`、`b` 必须不同侧：

```cpp
unite(a, b + n);
unite(a + n, b);
```

原来写不出来的「异或 1」，被摊成了两句「相同」。

### 判冲突

```cpp
if (same(a, b)) { /* 塞不进去，冲突 */ }
```

`same(a, b)` 成立 → a、b 早已被逼同侧，这条约束加不进去。

> ⚠️ `same(a, a + n)` 也能说明矛盾，但它要等到**下一条边**才暴露出来，
> 判定的时机和答案值都会错。不要拿它当主判据。

### 为什么 `i + n` 让「翻面」免费

块整体翻面 = 把所有 `i` 和 `i + n` 互换。

```
union(i, j+n)   翻面后等价于   union(i+n, j)   ← 这句本来就在
```

所以翻面**一条 union 都不用改**。固定编号的方案做不到 —— 翻面等于把整块人搬家，而并查集搬不了家。

### 正确性

- **无冲突**：没有集合同时含 `i` 和 `i+n` → 每个集合可独立赋一个真值、与它互补的集合赋反值 → 得到合法分配
- **有冲突**：推出「i 既在 A 又在 B」→ 无解

## 四、带权并查集（关系放在边权上）

### 4.1 框架是死的，语义是活的

`find` 的写法永远一样，三行顺序不能动：

```cpp
int find(int x) {
    if (x == fa[x]) return x;
    int t = fa[x];          // ① 先存旧父亲
    fa[x] = find(fa[x]);    // ② 递归到根并压缩
    d[x] += d[t];           // ③ 补上「旧父亲到根」这一段
    return fa[x];
}
```

- `t` 必须在递归**前**存：递归会把 `fa[x]` 改成根，之后就取不到旧父亲了
- `d[t]` 必须在递归**后**读：此时 `d[t]` 才是 t 到根的距离（递归里刚更新过）

**真正要自己推的只有两件事：**

1. `d[x]` 是什么语义
2. 合并时 `d[新根] = ?`

### 4.2 三道题，三种语义

| 题 | `d[x]` 语义 | 合并公式 | 合并方向 |
| --- | --- | --- | --- |
| P1525 关押罪犯 | 与根的异或（0 同侧，1 异侧） | `d[ra] = d[a] ^ d[b] ^ 1` | 无向 |
| P8779 推导部分和 | 前缀和的差值 | `d[lf] = d[r] - d[l] + v` | 无向 |
| P1196 银河英雄传说 | x 前面有几艘船（位置） | `d[lf] = sz[rf]` | **有向** |

`find` 一样，`d` 的定义和合并公式完全不一样。**照抄公式必错。**

### 4.3 P1196 银河英雄传说

题意：`M i j` 把 i 所在整列接到 j 所在列的**尾部**；`C i j` 问同一列时两人之间隔了几艘船，不同列输出 -1。

**`d[x]` 的定义**：从队首数，x 前面有几艘船（0-based 下标）。

**合并**：lf 整列接到 rf 列的尾部，所以 lf 这个队首前面正好多了「rf 列的全部船」：

```cpp
father[lf] = rf;
d[lf] = sz[rf];        // 必须用合并前的长度
sz[rf] += sz[lf];
```

**查询**：同列时两船之间的船数 = 下标差 − 1：

```cpp
if (find(l) != find(r)) return -1;
return abs(d[l] - d[r]) - 1;
```

**手算一遍**（初始三艘船各自一列，`sz` 全为 1，`d` 全为 0）：

```
M 1 2 : find(1)=1, find(2)=2  → fa[1]=2, d[1]=sz[2]=1, sz[2]=2
        序列变成  2  1

M 1 3 : find(1)=2, find(3)=3  → fa[2]=3, d[2]=sz[3]=1, sz[3]=3
        序列变成  3  2  1

C 1 3 : find(1) 压缩时 t=fa[1]=2, d[1] += d[2] → d[1]=1+1=2
        d[1]=2, d[3]=0  →  |2-0|-1 = 1     (中间隔着 2 号)
```

**易错点**：
- ❌ `d[lf] = sz[rf]` 写成合并后的总长
- ❌ 查询写成 `d[l] - d[r]`（少了 `abs` 和 `-1`）
- ❌ 不同列没返回 -1

### 4.4 P8779 推导部分和

题意：已知若干区间 `[l,r]` 的和，回答询问区间的和，推不出来输出 UNKNOWN。

**做法**：转成前缀和。令 `S[i] = a1 + ... + a_i`，区间 `[l,r]` 的和就是 `S[r+1] - S[l]`。

**`d[x]` 的定义**：x 与父亲的前缀和差值。

**合并**：已知 `S[w] - S[u] = v`，把 u 的根挂到 w 的根下：

```cpp
father[ru] = rw;
d[ru] = d[r] - d[l] + v;     // 这里的 v 是题目给的,不是算出来的
```

**关键**：`r + 1` 是必须的 —— 区间转前缀和节点，下标整体偏移一位。**这个 `+1` 只属于这一类题，别搬到别的题去。**

### 4.5 为什么两题不能互抄

| | P8779 | P1196 |
| --- | --- | --- |
| 偏移量从哪来 | **外部输入**：题目直接给你 v | **内部状态**：目标列的长度 sz |
| 合并方向 | 无向，谁挂都行，公式对称 | 有向，i 列必须接在 j 列后面 |
| 编号 | 前缀和节点，要 `r+1` | 就是船号，不偏移 |
| 本质在模拟什么 | 代数等式系统（电势、相对值） | 序列拼接（绝对下标、几何位置） |

**一句话**：P8779 是「约束驱动」，P1196 是「状态驱动」。

P1196 里根本没有题目给的数字可用，偏移只能从 `sz` 来；P8779 里即使不知道任何长度也能合并，因为 `v` 已经给了。走错源头，公式就必然对不上。

## 五、例题：洛谷 P1525 关押罪犯

**题意**：n 个人分两个监狱，每条仇恨边 `(a,b,v)` 若两人同监狱就产生 `v` 的冲突，求怎么分能让最大冲突最小。

### 转成约束系统

1. 按 `v` 从大到小排序
2. 依次要求 `a`、`b` 分到不同侧
3. 第一条塞不进去的边，它的 `v` 就是答案
4. 全部塞得进去 → 输出 `0`

### 为什么第一条失败的边就是答案

```
比它大的边全部满足  →  最大冲突 ≤ v
它自己做不到        →  最大冲突 ≥ v
上下夹住,答案 = v
```

### 代码骨架

```cpp
sort(e + 1, e + m + 1, cmp);   // 按 v 降序

int ans = 0;
for (int i = 1; i <= m; i++) {
    if (same(e[i].a, e[i].b)) {   // 先判
        ans = e[i].v;
        break;
    }
    unite(e[i].a, e[i].b + n);    // 再并
    unite(e[i].a + n, e[i].b);
}
cout << ans;                      // 无冲突时仍是 0
```

### 这题踩过的坑

- ❌ `ans` 写成「最后一条成功合并的边的 v」→ 答案要的是「第一条失败的边」
- ❌ 无冲突的图不 `break`，输出成了最小边的 `v`（应该输出 `0`）
- ❌ 判冲突对象写成 `same(a, a + n)` → 要看的是当前这条边能不能塞进去

## 六、写代码时的易错点

- **参数传值** `vector<int> father` → 每次调用复制整个数组，路径压缩全废，必 TLE。写 `vector<int>&` 或直接用全局数组
- **拆点题数组开 2n**，不是 `n + 1`
- **带权并查集不要跨题抄公式**：`find` 可以抄，`d[x]` 的语义和合并公式必须自己按题推
- **前缀和的 `r+1` 只属于「区间转前缀和」这一类题**，搬到别的题就是错位
- **递归 find 在长链上可能爆栈**，规模大时改迭代
- **`union` 只改根节点**，别动非根节点
